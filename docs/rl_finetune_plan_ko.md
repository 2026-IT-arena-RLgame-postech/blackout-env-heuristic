# 대전 기반 RL 미세조정 계획: GRPO vs PPO (2026-10-20)

## 배경과 순서

- 헌터 밸런스 패치가 예정되어 있다. 패치 이후 순서: **휴리스틱 재작성·튜닝 → 증류(학생) → RL 미세조정**.
- RL 단계에서는 GRPO와 PPO를 **같은 예산, 같은 상대 풀, 같은 평가**로 비교한다. 가치망(S1, `blackout_env/value/`)이 이미 있어 PPO의 critic을 따뜻하게 시작할 수 있다.
- 보상: 승패를 주 보상으로 하고, 점수차는 포화시켜 보조로만 쓴다. 약한 상대에게 점수차만 불리는 학습을 막기 위해서다(약한 상대는 승률로 판단하는 원칙).

## 공통 기반 (두 방법이 같이 쓰는 것)

| 항목 | 내용 | 기존 코드 |
|---|---|---|
| 환경 | 파이썬 시뮬(S2)에서 학습한다. Unity는 평가에만 쓴다. | `sim/state.py` (`SimState.copy()`), `sim/batch.py` (`BatchSim`, `BatchRollout`) |
| 정책 | 증류 학생(무상태 MyModel)에서 시작한다. | `NetPolicy` |
| 상대 풀 | 휴리스틱(V32.1 등), 증류 학생, 과거 RL 체크포인트. 지기 쉬운 상대를 더 자주 뽑는 PFSP로 샘플링한다. | `train/distill/opponents.py` |
| 보상 | `r = 1[win] − 1[loss] + λ·tanh(margin / s)`, λ≈0.2, s는 점수 분포를 보고 정한다. | — |
| 기준 고정 | 증류 정책 π_ref에 대한 KL 항과 BC 보조 손실(작은 가중치)을 둔다. | 증류 손실 재사용 |
| 평가 관문 | 기존과 같다: 64 → 256 → 1024 시드, OOD 규칙(§56.6), 약한 상대 승률 규칙(§58.6), Elo-24 추가, 마지막에 Unity 확인. | `examples/elo24.py` 등 |

### 새로 만들어야 하는 것

1. **확률적 행동과 log-prob**: 지금 `decode_moves`는 argmax다. 유닛별 bin을 범주형 분포에서 샘플링하고, 행동 log-prob = 유닛별 log-prob의 합으로 계산해야 한다. 각도 offset은 1차로는 결정적으로 둔다(정책 경사 밖). 필요하면 이후 가우시안으로 바꾼다.
2. **배치 휴리스틱 상대**: `HeuristicPolicy`는 경기마다 하나씩 도는 느린 참조 구현이다. 상대 풀의 휴리스틱 비중이 크면 이것이 병목이 된다. 그러면 numba로 옮기거나 프로세스 병렬화를 한다.
3. **분기 롤아웃 수집기**: 실제 경기 궤적에서 시점 t를 뽑아 `SimState.copy()`로 K개로 갈라 짧게(H초) 굴린다. GRPO의 그룹이고, PPO에서도 분산 비교용으로 쓴다.
4. **패치 반영**: 밸런스 패치 후 시뮬을 Unity 기록 궤적과 다시 맞춘다(`examples/sim_validate.py`). **이것이 RL 착수의 선행 조건이다.**

## A. GRPO

- **그룹 구성(2단계)**
  - A1 매치 그룹: 같은 맵 시드, 같은 상대, 같은 진영으로 K=8~16판을 돌리고 최종 보상으로 정규화한다. 구현은 가장 쉽지만 결정 수가 많아 신호가 noisy하다. 기준선으로만 쓴다.
  - A2 분기 그룹 (본안): 시점 t의 상태에서 K개로 분기해 H초를 롤아웃하고, 끝나지 않은 가지는 가치망으로 bootstrap한다(`G = r_H + V(s_{t+H})`). advantage `A_k = (G_k − mean) / (std + ε)`. 손실은 분기 구간의 결정들에만 준다. 분기 시점 t는 승부가 갈리는 구간(경주, 교전)에 가중한다.
- **손실**: clipped ratio(ε=0.2) · A + β·KL(π‖π_ref) + α·BC. 그룹 안 std가 0에 가까우면(결과가 확정된 상대) 그 그룹은 버리고, PFSP 가중치에 반영한다.
- **의미**: A2는 "그룹 평균 baseline + 가치 bootstrap"이라 사실상 PPO와 GRPO의 중간이다. 순수 critic-free 효과를 보려면 A1과 함께 비교한다.

## B. PPO

- **Critic**: S1 가치망(트렁크 공유 가능)에서 시작한다. 출력 중 `P(win)`과 최종 lead를 보상 정의에 맞춰 `V = P(win) − P(loss) + λ·E[tanh(margin/s)]`로 조합하거나, 같은 정의의 새 머리를 짧게 미세조정한다. 정책 업데이트 전에 critic만 먼저 몇 백 step 맞춘다(warm-up).
- **수집**: 전체 경기를 on-policy로 수집한다. GAE(γ≈1, λ_GAE 0.95), 보상은 경기 끝에서만(희소) 주고 점수차 항은 끝에서 한 번 준다.
- **손실**: clipped PPO + 가치 손실(Huber) + β·KL(π‖π_ref) + α·BC + 작은 엔트로피 항.
- **주의**: 정책과 critic이 트렁크를 공유하면 초반에 가치 손실이 정책을 망가뜨릴 수 있다. 1차는 **분리된 critic**(S1 체크포인트 복사본)으로 간다.

## 비교 실험 설계

| 런 | 방법 | 비고 |
|---|---|---|
| R0 | 증류 학생 그대로 | 기준 |
| R1 | PPO (분리 critic, 전체 경기) | |
| R2 | GRPO-A1 (매치 그룹) | critic 없음 |
| R3 | GRPO-A2 (분기 그룹 + V bootstrap) | 본안 |

- 같은 환경 step 예산(예: 동일 transitions 수), 같은 상대 풀 시드, 같은 KL·BC 가중치로 돌린다.
- 지표: 중간 체크포인트마다 대 상대 풀 승률·점수차, OOD worst-case, KL(π‖π_ref). 최종 후보만 관문 절차에 올린다.
- 먼저 짧은 파일럿(각 런 수 시간)으로 학습 신호가 있는지(승률 기울기, std≈0 그룹 비율) 보고, 이긴 쪽만 길게 돌린다.

## 패치 전에 할 수 있는 일 (패치와 무관)

1. 확률적 행동/log-prob과 `NetPolicy` 샘플링 모드 (+ 테스트: argmax 모드와 bit-exact)
2. 분기 롤아웃 수집기(`SimState.copy()` 기반)와 PFSP 상대 샘플러
3. GRPO/PPO 트레이너 뼈대. 현재 버전(P24c 시작)으로 1시간짜리 연기(smoke) 런을 돌려 파이프라인을 검증한다. 결과 자체는 패치 후 버린다.
4. 휴리스틱 수치 파라미터화. 패치 후 코드를 고치기보다 튜닝/탐색으로 빠르게 재조정하기 위해서다.

## 패치 후 재증류 때 함께 할 A/B: 36토큰 ViT 인코더 (2026-10-20 결정)

- **목적**: CNN 인코더(`GraphicEncoder`)를 ViT식 패치 임베딩으로 바꿔도 되는지 확인한다. 재증류는 어차피 처음부터 하므로 웜스타트를 잃는 비용이 없다.
- **팔**
  - A: 현행 MyModel(CNN → 6×6 = 36 시각 토큰)
  - B: 24×24 지도를 4×4 패치로 나눠 6×6 = 36토큰으로 선형 임베딩(필요하면 얇은 conv stem 1층). trunk, RoPE, 유닛/전역 토큰, 헤드는 그대로 둔다. 시각 토큰 수가 같아서 인코더 효과만 분리된다.
- **조건**: 같은 교사, 데이터, 스텝, 시드 2개 이상(경주 복권 때문, §25·§26).
- **지표**: 보류 정확도(첫 10초 열, sim DAgger 보류 열), 대 V19·P5a급 민감 상대 강도, step 시간.
- **채택 기준**: 기존 관문 절차를 그대로 따른다.
- **비용 근거** (P24c 실측 2026-10-20): 185 MMAC/forward 중 CNN 25 MMAC(14%), trunk Linear 145 MMAC(78%). MPS 시간 비중 11~12%, CPU B=64에서는 44%. B는 비용이 약 10% 줄어들 것으로 예상한다.
- **2×2 패치(144토큰)**: trunk 비용이 약 3배가 된다. B가 A와 비슷하거나 나을 때만 추가로 시험한다.
- **선행 증거**: §26 롤아웃망에서는 ViT식 64토큰 `patch_*`가 f3(CNN 36토큰)보다 같거나 약했다. §25에서는 지도 경로를 더해도 이득이 없었다. 기대 이득은 작고, 단순화가 주목적이다.

## 미정 / 결정 필요

- 각도 offset을 확률적으로 할지
- 상대 풀의 신경망 비중, 자기 자신(self-play) 포함 여부
- 기억 있는 학생(KDA)로 갈 경우 PPO/GRPO 모두 순환 상태 처리 필요. 1차는 무상태 학생으로 한다.
