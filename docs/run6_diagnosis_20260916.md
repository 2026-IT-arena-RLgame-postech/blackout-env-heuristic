# Run 6 종료 후 진단 — 2026-09-16

Run 6(200k, `checkpoints/offline/20260915-235937_61813/final.pt`)이 V4에 30전 전패로 끝난 뒤,
"무엇이 실력을 막고 있는가"를 측정으로 좁힌 기록. 모든 수치는 최종 체크포인트를 V4와 붙여 얻었고,
진단 스크립트는 세션 스크래치패드에 있다(재사용하려면 리포로 옮길 것).

결론부터: **벽 막힘은 증상이고 원인이 아니다.** 실제 병목은 (1) 배터리를 주우러 가지 않는 것과
(2) 두 진영이 서로 다른 좌표계로 학습돼 유효 데이터가 절반이 되는 표현 문제다.

## 1. 막힘은 경기 중반부터 시작되고, 한 번 걸리면 오래 간다

10경기를 틱 단위로 기록(막힌 유닛 비율, Q 마진, Q 최대값, 점수차).

| 틱 구간 | 막힌 유닛 비율 | Q 마진 | Q 최대값 |
|---|---|---|---|
| 0–50 | 1.4% | 2.14 | −0.1 |
| 50–100 | 12.4% | 1.25 | −2.4 |
| 100–150 | 25.3% | 1.03 | −3.2 |
| 150–200 | 33.0% | 0.88 | −4.2 |
| 200–450 | 31~34% | 0.83~0.95 | −4.8~−7.9 |
| 500+ | 20~23% | 0.46~0.84 | −11~−16 |

팀의 40% 이상이 막힌 구간은 평균 69틱, 최대 381틱 이어진다. 경기 10개 중 5개는 전체 틱의 40% 이상을
그 상태로 보낸다. 정책이 결정적이라 막히면 관측이 거의 안 변하고 같은 방향을 다시 고르는 고리가 생긴다.

## 2. 원인은 휴리스틱 데이터의 행동 다양성이 아니다

"후반으로 갈수록 데이터가 다양해져 Q가 흔들린다"는 가설을 데이터셋(100만 전이, 2107경기)에서 직접 쟀다.
틱 구간별 휴리스틱 행동 엔트로피는 **0–50틱 2.78, 400–500틱 2.86(최대 3.0)으로 사실상 평평하다.**
연속 틱 사이 행동 변경 비율만 0.39 → 0.50으로 조금 오른다. 가설은 기각.

대신 **분포 이탈**이 보인다. 같은 모델을 두 종류의 상태에서 재면:

| 상태 출처 | Q 최대값(후반) | 휴리스틱 행동 일치율 |
|---|---|---|
| 데이터셋(휴리스틱이 방문) | 약 −1 ~ +1 | 0.50 → 0.41 |
| 모델 자신의 경기 | −0.1 → −11 | — |

후반 상태 자체가 어려운 게 아니라, 모델이 자기 궤적을 따라 데이터에 없는 상태(벽에 붙어 멈춘 상태,
휴리스틱은 1.3~2.3%만 겪는다)로 흘러가 거기서 가치 추정이 무너진다.

## 3. 막힘을 없애도 점수는 그대로다

재학습 없이 Q 테이블에서 행동을 고르는 방식만 바꿔 비교(각 10~20경기, 세 번의 독립 실행).

| 방식 | 막힘 비율 | 점수차 |
|---|---|---|
| argmax(현행) | 24.7~29.0% | −54.7 / −61.6 / −68.5 |
| 벽 방향 마스킹 | 0.3~1.3% | −78.5 / −66.0 / −57.4 |
| ε=0.15 | 14.1% | −54.5 / −52.9 |
| 볼츠만 T=0.5 | 10.6% | −61.4 |
| 마스킹 + ε=0.05 | 0.0% | −72.1 |

**막힘은 완전히 제거되지만 점수차는 표본 잡음 범위 안에서 그대로다(50경기 가중평균 argmax −63.0,
마스킹 −65.1).** 유닛이 24%의 시간을 벽에 붙어 보내는데도 점수가 안 변한다는 것은, 그 시간에 제대로
움직였어도 득점으로 이어지지 않았을 것이라는 뜻이다. 막힘 penalty를 낮추거나 탈출 데이터를 넣는 방향은
실력을 올리지 못할 가능성이 높다.

## 4. 끊기는 지점은 "줍기"다

같은 경기에서 모델과 상대 휴리스틱을 동시에 측정(10경기).

| 지표 | 모델 | 휴리스틱 V4 |
|---|---|---|
| 배터리 줍기 | 113회 | 213회 |
| 창고 배달 | 84회 | 201회 |
| 운반 중 잃음 | 28회 | 10회 |
| 배터리 보유 시간 | 17.5% | 29.8% |
| 짐 없을 때 배터리 접근 속도 | **−0.003/틱** | −0.013/틱 |
| 짐 있을 때 창고 접근 속도 | +0.079/틱 | +0.105/틱 |

**짐을 들면 창고로는 간다**(접근 속도 휴리스틱의 75%, 주운 것의 74%를 배달). **문제는 절반만 줍는
것이고, 짐이 없을 때 배터리로 다가가는 속도가 사실상 0이다.** 배터리 접근은 네비게이션 potential Φ가
직접 보상하는 부분이므로, 이 신호가 학습되지 않고 있다는 뜻이다.

## 5. 두 진영이 서로 다른 좌표계로 학습되고 있었다

관측 파이프라인은 Team B에게 **채널 이름만 바꿔준다**(`MyObsPreprocessor.flip_team_perspective`가
SPAWN/STORAGE의 아군·적군만 교환). 격자도, `agent_states` 행 순서도, 행동 프레임도 월드 좌표 그대로다.

- 데이터셋에서 확인: 버퍼 a의 아군 스폰 중심 (1, 1), 버퍼 b는 (22, 22).
- Team B일 때 자기 유닛은 5~9행에 있고, `MyModel`은 유닛 번호 0~9에 묶인 학습 임베딩을 쓴다.
  아군 슬롯이 진영마다 다른 임베딩을 차지한다.
- 행동 (dx, dy)도 두 팀 모두 월드 기준이라 "아군 창고 방향"이 진영에 따라 반대다.

즉 오염(관측과 행동의 프레임 불일치)은 **없지만**, 네트워크는 파랑용 과제와 빨강용 과제를 각각 절반의
데이터로 따로 배우고 있었다. 실측 비대칭(경기 20개, 진영당 10개): 막힘 비율 Team A 30.2% 대
Team B 18.9%, 점수차는 −68.7 대 −68.3으로 동일.

맵은 y=x 대각선 대칭이다(Unity `RegionData.CreateSymmetricRegion`, `posB = (posA.y, posA.x)`).
실제 관측 3개 지점에서 벽·공백·사이트 채널이 대각 전치에 대해 대칭이고 아군/적군 스폰·창고가 서로의
전치임을 확인했다(`tests/test_team_frame.py`).

## 6. 반영한 코드 변경

### 6.1 진영 정규화 (`blackout_env/env/team_frame.py`)

Team B 시점을 Team A가 보는 프레임으로 되돌린다. 격자는 반대각 전치 `(r, c) → (H−1−c, W−1−r)`,
위치는 `(x, y) → (y, x)`, 유닛 행은 `k → (k+5) % 10`(아군이 0~4행), 행동 인덱스는 `i → (2−i) % 8`.
격자가 정사각이고 유닛 10행을 5칸 두 번 돌리면 제자리이므로 **네 변환 모두 involution**이다. 즉 같은
함수가 정규화와 역변환을 겸한다.

적용 지점:
- 학습: `QMIXTrainer._mirror_batch`가 스트림 b 배치(graphic/boot/future, agent_states, actions,
  action_window)에 적용. **저장 데이터는 월드 좌표 그대로 두고 배치 조립 때 변환**하므로 30GB
  데이터셋을 다시 쓸 필요가 없고, 기존 수집 스크립트도 그대로다.
- 수집: `select_actions`가 Team B 관측을 정규화해 넣고 고른 방향을 월드로 되돌린다.
- 추론·평가: `MyPolicy.act`도 같은 경로.

기대 효과는 **유효 데이터 2배**다. 기존 체크포인트는 Team B 프레임이 달라져 호환되지 않는다(재학습 필요).

### 6.2 벽 방향 마스킹 (`blackout_env/model/action_mask.py`, `QMIXConfig.action_masking`)

벽으로 들어가는 방향을 **greedy 선택에서만** 제외한다(행동 선택, 수집, Double-DQN 부트스트랩 행동).
저장된 행동의 Q에는 적용하지 않는다 — 휴리스틱도 가끔 벽으로 가고, 그 전이는 실제로 실행한 행동의
가치를 그대로 학습해야 한다. 대각 이동은 양옆 칸이 모두 통행 가능할 때만 허용해 휴리스틱의 규칙과 맞췄고,
사방이 막힌 유닛은 마스크를 걸지 않는다(전부 −inf 방지).

3번 표에서 보듯 실력은 오르지 않지만 두 가지 이득이 있다.
- 리턴에서 막힘 penalty가 사라져 게임 리워드 중심이 된다(Run 6에서 penalty가 리워드의 1.4~2.4배였다).
- 막힘에 가려졌던 방향 선택의 질을 지표로 직접 볼 수 있다.

실제 평가 경로(`periodic_eval` + `MyPolicy`) 검증: 1000틱당 막힘 사고 **2.71 → 0.188**
(상대 휴리스틱 0.314보다 낮다), 점수차 −74.5 → −72.3.

### 6.3 유닛 채널 (`blackout_env/model/unit_channels.py`)

막힘의 원인을 전수 분류해 보니 **막힌 5,074 유닛틱의 100%가 앞칸이 벽이었고, 유닛 충돌은 0건이다.**
오히려 앞칸에 유닛이 있는데 정상 이동한 경우가 619회(아군 522, 적군 97) 있다 — **유닛끼리는 서로를
막지 않고 겹쳐 지나간다.** 따라서 유닛 채널은 벽 막힘 대책이 아니다.

넣는 이유는 4번의 운반 중 손실(모델 28회 대 휴리스틱 10회)이다. "내 운반수 근처에 적이 있나",
"적 운반수가 어디 있나"는 유닛이 맵 위에 그려져 있어야 컨볼루션이 지형과 엮어 볼 수 있는 판단인데,
기존 13채널에는 유닛이 아예 없었고 위치는 `agent_states` 좌표 10줄로만 들어갔다.

추가한 4채널: 아군 수, 적군 수, 아군이 든 배터리량, 적군이 든 배터리량. 존재 플래그가 아니라 **개수**인
이유는 유닛이 겹칠 수 있기 때문이다. 아군/적군은 `agent_states`의 팀 부호 열로 가르므로 정규화된
프레임에서도 그대로 동작한다.

**저장하지 않고 `MyModel.forward`에서 매번 그린다.** `agent_states`만 있으면 결정되는 값이라
재수집도, 디스크 추가 60GB도 필요 없고, 대칭화 이후에 그려지므로 프레임이 자동으로 맞는다.
`GraphicEncoder`의 입력 채널은 13 → 17이 되어 **기존 체크포인트는 로드되지 않는다**(형상 불일치로
즉시 에러).

### 6.4 마스킹은 기본값 off

막힘이 전부 벽인데 벽 채널은 이미 관측에 있으므로, 회피는 모델이 배워야 할 것으로 두고
`action_masking=False`를 기본으로 했다. 손으로 만든 마스크는 "모델이 배웠는지"를 가려버린다.
막힘 penalty를 리턴에서 빼고 싶을 때나, 대칭화 이후에도 막힘이 남을 때 켜는 대비책으로 남긴다.
